Brand Guideline マニュアル

CSSスタイル・構造化データ・画像・スタイルスケープをまとめて閲覧、編集、共有することを想定したツールです。
見出し・変数名・値・リスト項目をクリックしてそのまま編集し、htmlコピー、一括ダウンロード、ローカルファイルを更新などが可能です。
一部の変数は、あえてページ内で使用しており、即時反映されます。

各ボタンは index.html を file:// で直接（ダブルクリックなどで）開いていると動作しません。
ターミナルで下記コマンドを実行してください。1行目でダウンロードしたフォルダへ移動し、2行目でローカルサーバーを起動します。
※Downloadsフォルダに保存された場合
cd ~/Downloads/brand-guideline
python3 -m http.server 5173
実行後、ブラウザで http://localhost:5173/index.html を開いてください。

HTMLをコピー
閲覧用の単一HTML（CSS込み・JSなし）をクリップボードへコピーします
ZIPをダウンロード
この編集ツール一式（HTML/CSS/JS/README）をダウンロードします
ソースに保存
フォルダ選択ダイアログが開きます。ダウンロードしたフォルダ（brand-guideline）を選択すると、フォルダ内の index.html と style.css が現在の編集内容でそのまま上書きされます。以後は同じフォルダを選び直す必要はなく、保存のたびに直接上書きされます。 Safari / Firefox は非対応です。Chrome / Edge で開いてください。Brave は brave://flags/#file-system-access-api を Enabled にして再起動すると使えます。

リロードすると初期値に戻ります。ローカルストレージ保存は実装予定。

セクション

  • Hero（MindMap FV）

    ・背景はCoding/Design/Frontendの3本の動画をcontrast-75%でマスク合成し常時ループ再生
    ・「Coding」「Design」「Application」のラベル枠がそれぞれ固有色（wine/brown/forest）のグラデーション窓になっており、内側に動画の一部がのぞく
    ・数字（3.5、2025/05）だけ太字イタリックで強調された装飾フォントの経歴コピー

  • Experience and Dependencies

    ・横方向パララックス（ScrollXSection）で縦スクロールに応じ、ツール名の文字列群（Cursor、Claude Code、TailwindCSS、WebGL、Codex等）が異なる速度で左右にずれながら流れる
    ・前セクションのColoring/Application/Designラベル枠が画面内に残り、テキストと重なって透過して見える
    ・画面下端にグレー半透明の帯で技術スタック名が固定表示され続ける
    ・「Details」ボタンで全画面ダイアログが開き、経験年数・使用ツール一覧がカード3列のdl形式で表示される

  • Vibe or Vault Driven

    ・白背景のまま「Vibe/Design」と「Vault/Driven」を対角線上に配置し、その間に極薄グレーの巨大な「or」の文字を透かしのように重ねる
    ・右側にAI活用の説明文と、クリックで開閉する「Thinking...」トグル欄（考察テキスト）がある

  • Bunmyaku Teaser

    ・紺色背景に切り替わり、剣と盾を組み合わせた大きな線画モチーフ（SVG）が中央に浮かぶ
    ・背景全面に星空のような細かいドットが散っている
    ・スクロールに応じて剣のモチーフが上方向へスライドしていく

  • Repulsion Lists

    ・白背景に戻り、直前セクションの剣モチーフの残像が薄く重なりながらフェードアウトする
    ・個人制作のツール名カード群（Random Generator、Shuffle Divide、Glitch、Agent Driven CMS等）が敷き詰められ、カーソルに反応して反発移動する物理演算アニメーションになっている

  • Coding

    ・背景が赤に切り替わり、中心から放射状に広がる細い光線のアニメーション背景になる（中心に明滅するグローの円）
    ・巨大な半透明の「Coding」の文字が透かしとして常に背面に表示される
    ・制作フロー（HTML作成→テーマ構築→管理画面設計→スキル作成）が、曲線と丸ポイントで繋がれたノードグラフ状のカードで表現される
    ・過去の制作サイトのプレビュー画像カードがPage/Repoリンク付きで線に沿って次々に現れる

  • Design

    ・背景が黄土色の市松模様になり、スクロールに応じて正方形の並びから45度回転したひし形（×柄）へと徐々に回転していく
    ・巨大な半透明の「Design」の文字が透かしとして表示される
    ・実績テキストの一部（Photoshop、250案件など）が黒背景に白文字のハイライト帯で強調される
    ・「External Link」「GPT Imageレポート」等、黒背景のボタン/リンクが並ぶ

  • Frontend

    ・背景が緑になり、格子状のワイヤーフレームと色収差的ににじんだ抽象グラフィックが斜めに重なる
    ・巨大な半透明の「Application」の文字が透かしとして表示される
    ・開発ツール一覧が下線付きリンクのリストとして縦に並ぶ

  • Footer

    ・背景色が反転して黒基調になり、左下に山並みのアウトラインSVG（fff2.svg）が敷かれる
    ・Name/Hobby/Specialtyのプロフィール定義リストと、個人制作物・外部リポジトリへのリンク一覧が中央揃えで並ぶ

意思決定・設計判断・ガイドライン

snake_caseのCSS設計、命名規則（簡易BEM）
ハイフンx2のアンスコx2の代わりにアンダースコア1つ。子要素は親ブロック名を引き継ぐ（header_actions, sections_grid）。swatchなどブロック名ではない一単語クラスはある。（孤立してるので弊害なし）
CSSクラス略語ルール
BEMブロック名では不可。誰でも理解できる略語だけ許可。design_noteをdn_などにしない
BEMブロック名は一単語
header_bar ❌ header ○, var_group ❌ variable ○
別パターンのスタイル上書き
共通クラス+モディファイア（例：swatch + is_color / is_size）
aspect-ratioの活用
width=heightならaspect-ratio:1、インラインの時widthだけで済む
BEMとユーティリティ
.BorderTなどユーザーのテンプレートクラス、使い回すスタイルはユーティリティクラスとして使う。BEM風セマンティッククラスは印としてスタイルがなくても場合によっては書く。複雑な構造なら必要な時に追加する
BEM風クラスの完全適用
クラス+タグセレクタ指定（li, h3等）は基本禁止、BEM風にしてる意味がない。下記ケースで:whereを使う例外あり。
BEM風クラス子要素の:where()
シングルクラス内で`:where`を使い、BEM風クラスの数を増やさず、且つセレクタを複雑にしないまま詳細度を保つ。ユーザーが編集しづらくなる場合BEMクラスを省略する
ブロック名は略語を使わず一単語で最適な名前を考える
BEMのトップレベル（ブロック）名は略語ではなく意味の通る1語にする。
編集可能コンテンツのセレクタ指定。.editable 汎用jsフック
JSファイル上の全てのセレクタをエディタブルで済ませるとHTMLが冗長になるため汎用性のために追加。
マニュアルはリストではなくテキストブロック
何の説明もなければ、改行のためにPタグやULリストを選択しない。BRタグ優先。
規則や制約のドキュメントに詳細な経緯や具体例を文章で書かない。
後から読むエージェントに伝えても意味がない。論理的な短い言葉で書く。難解なら、例を構造化して書く
